# Access DDL comparison harness

Replays Access DDL generated by the VS Code extension (`netezza.createDDL` on a
Microsoft Access connection) into a fresh empty Access file using the
[`JustyBase.UCanAccessCs`](https://github.com/justybase/JustyBase.UCanAccessCs)
port, then compares the resulting table schema with the source file.

This verifies that the generated `CREATE TABLE` statements are replayable and
round-trip the schema: column name, data type, length, AutoNumber flag,
precision/scale and primary key must match the original Access file.

## Setup (one time)

Requires the .NET SDK (net10.0 or newer).

```bash
tools/access-ddl-compare/bootstrap.sh   # clones JustyBase.UCanAccessCs into tools/access-ddl-compare/.clone/
dotnet build tools/access-ddl-compare   # restore + build (NuGet: JustyBase.NetezzaSqlParser, Microsoft.Data.Sqlite)
```

## Usage

1. In VS Code, connect to an Access file, right-click a table → **Create DDL**,
   and save the generated SQL to a file (or export the whole database with
   **Export DDL**).
2. Run the harness:

```bash
dotnet run --project tools/access-ddl-compare -- --source /path/source.accdb --ddl /path/generated.sql
```

When using a checkout outside the default `.clone/` directory, use the wrapper
so the `--repo` path is supplied to both the application and MSBuild:

```bash
tools/access-ddl-compare/run.sh --source /path/source.accdb --ddl /path/generated.sql --repo /path/to/JustyBase.UCanAccessCs
```

Options:

| Option | Meaning |
|--------|---------|
| `--source <path>` | source `.mdb`/`.accdb` file (required) |
| `--ddl <path>` | generated Access DDL file (required) |
| `--keep-target <path>` | keep the replayed file at this path (default: temp file) |
| `--version <ver>` | target file version: `2003` (default for `.mdb`), `2007`, `2010` or `2016` |
| `--repo <path>` | path to an existing JustyBase.UCanAccessCs checkout (default: `.clone/`; use `run.sh` for an external checkout) |

Exit codes: `0` — all shared tables match; `1` — differences found; `2` — usage or setup error.

## What is compared

For every table present in both files: each column's `(name, DataType,
length, AutoNumber, precision, scale)` in column order plus the primary-key
index columns. Tables listed as "EXTRA table in replay" are expected when the
DDL export covers only part of the database (e.g. a single object).
